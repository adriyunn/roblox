# PARITY rows, F2 and later (About Fishing mechanics beyond F1)

**Written by Cloud, 2026-10-06, WITHOUT the project files. Dev3 merges these rows into
`PARITY_CHECKLIST.md` after checking the column shape against the real file.** Ids: X60-X68 for rows
that extend the fishing systems that exist in F1 (fish, cast, line, fight), P01-P20 for new systems.
Next free ids: X69, P21. Every row is NOT STARTED.

Reference behaviour comes from demo and convention builds shown March-September 2026 and is marked
UNVERIFIED until Adrian records it; "RECORD IN DEMO: V-nn" names the clip in
`clips/DEMO_CLIP_LIST.md` (V42 onwards, continuing the F1 numbering) that settles it. The GameOne
rule keeps every single-player mechanic per player on a Roblox server (one tackle box, wallet, clock,
unlock set and story state per player; the server owns them, the client only asks). Acceptance tests
are offline Luau suites where the logic is pure, naming the module that would hold it: `TackleBox`,
`SpeciesTable`, `GameData`, `CatchLog`, `SaveData`, `WorldClock` (proposed, none written yet; they
would live in `Fishing/Shared/` so both the server and offline tests can require them).

Phase guess: F2 = the loop that makes catching matter (species, box, selling, shop, lures, clock);
F3 = world (weather, places, caves, anchors, piloting, filleting, aquarium); F4 = story and town;
F5 = the opening and pacing. The Coordinator may move rows between phases.
